# Processing machines

| Machine | Inputs / outputs | Processing |
| --- | --- | --- |
| Electric Arc Furnace | 4 item lanes / 6 shared outputs | Current smelting recipes; 200 ticks and 8 FE per tick per running lane |
| Electric Rock Crusher | 3 item lanes / 6 shared outputs | MMDLib crushing recipes; 200 ticks and 12 FE per tick per running lane |
| Electric Oven | 1 item input / 1 output | Smelting recipes whose result is food; 100 ticks at 4 FE per tick |
| Electric Still | 1 input tank / 1 output tank, 1,000 mB each | Power Advantage distilling recipes; recipe time at 16 FE per tick |
| Petro-Plastic Refinery | 2,000 mB oil tank / 1 item output | 100 mB crude or refined oil makes one ingot; 100 ticks at 12 FE per tick |

All five hold 500 FE and accept up to 4,096 FE per tick, through the electric cable network or any
other FE source.

## MMDLib XML machines

All five are declared in `src/main/resources/mmdlib/machine/*.xml`. MMDLib registers their blocks,
items, block entities, recipe types, capabilities, screens and JEI categories. Each extends MMDLib's
`base_powered_machine`, so its screen is MMDLib's standard machine screen: the slots and tanks, a
progress arrow per processor, a power gauge, and drawers for information, side configuration (with
automation addons), redstone and upgrades. Their block entity is EA3's `ElectricMachineEntity`; see
[MMDLib integration](mmdlib-integration.md).

**Lanes.** The furnace and crusher have one MMDLib recipe processor per lane (`lane_0`, `lane_1`, ...).
Each lane is bound to its own input slot (`input_0`, `input_1`, ...) and all share the `output` group,
so each lane keeps its own progress and a result must fit in the shared outputs before its lane
starts. Completion inserts the whole result and consumes exactly one input.

**Recipes.** Each declares its own MMDLib machine recipe type:

- `electricadvantage:arc_smelting`: generated by `processing.ElectricSmeltingRecipes` from every
  smelting recipe, at a fixed 200 ticks and 8 FE per tick.
- `electricadvantage:electric_crushing`: generated by `processing.ElectricCrushingRecipes` from every
  MMDLib `mmdlib:crushing` recipe, at a fixed 200 ticks and 12 FE per tick.
- `electricadvantage:oven_cooking`: generated by `ElectricSmeltingRecipes` with `products="food"` from
  every smelting recipe whose result is food, at a fixed 100 ticks and 4 FE per tick.
- `electricadvantage:electric_distilling`: generated by `processing.ElectricDistillingRecipes`, a copy of
  every Power Advantage `poweradvantage:distilling` recipe with 16 FE per tick added. Only
  fluid-to-fluid recipes using Power Advantage's `input` and `output` groups are copied.
- `electricadvantage:plastic_refining`: authored in
  `data/electricadvantage/recipe/plastic_refining.json`: 100 mB of `#poweradvantage:crude_oils` or
  `poweradvantage:refined_oil`, 1,200 FE, 100 ticks, one petro-plastic ingot.

Generated recipes copy their sources on every load and `/reload`, so recipes that datapacks,
CraftTweaker or KubeJS add to or remove from the source types reach these machines too. Generated IDs
are `electricadvantage:generated/<type>/<source namespace>/<source path>`; an authored recipe with the
same ID replaces one. All are MMDLib machine recipes, so CraftTweaker can edit them with
`<recipetype:electricadvantage:...>` or `mods.mmdlib.MachineRecipeBuilder`.

**Moving items and fluids.** These machines do not push their outputs into neighbours on their own.
Install an addon in the group's addon slots, in the side configuration drawer:

- Electric Advantage's **Item Output Port** pushes an item group into neighbouring inventories and the
  **Item Intake Port** pulls items in, 16 items per tick, with no power cost. They work in any MMDLib
  machine. See `automation/ItemPorts`.
- Power Advantage's **Fluid Intake Pump** and **Fluid Output Pump** do the same for tanks, as for Power
  Advantage's own Distillery.

Without addons, hoppers, pipes and other mods can still insert into inputs and extract from outputs,
on the faces the side configuration allows.

**Upgrades.** MMDLib's shared Gearbox Upgrade speeds every processor up (up to 2x with eight, at the
same FE per recipe) and the Capacitor Upgrade enlarges the buffer.

**Appearance.** Each uses the shared casing model `block/electric_machine_casing` (no front face) and
three front parts chosen by MMDLib conditions: `_front_on` while a processor is running,
`_front_powered` while the machine holds enough energy for one tick, `_front_off` otherwise. The item
models still show the full `_off` block.

**Redstone.** As in 3.0, a redstone signal on any face stops a new machine. Each face can be changed in
the redstone drawer.

**Worlds from 3.0 and 3.1.** The XML storage keeps 3.0's save keys and slot order: the furnace's and
crusher's items (inputs, then outputs), the oven's items, the refinery's plastic and oil, and the
still's input oil. 3.0's `Energy` key loads into the buffer, and 3.0 machines get 3.0's redstone
behaviour. Lost on upgrade: progress in a cycle, and the still's output tank (3.0 saved it separately,
under `Output`). The machines' hardness and blast resistance are now 3, from MMDLib's block settings.

## Verification

```sh
./gradlew --offline build
./gradlew --offline -PgameTests runGameTestServer
python3 scripts/validate_resources.py
xvfb-run -a ./gradlew --offline -PgameTests -PclientSmoke runClient
```

`ProcessingGameTests` cover four smelting lanes progressing together and resuming after a save, the
fixed 200-tick arc smelting, three crushing lanes with exact output counts, a two-item result that
must not start in one free space, live electric supply to a furnace exporting through an Item Output
Port, menus and crafting recipes, and 3.0 saves.

`XmlMachineGameTests` cover the oven's food filter and 100-tick cooking, the still running a Power
Advantage distilling recipe at 16 FE per tick, the refinery with both oils and a full output, loading
3.0 saves of all three, cable power reaching an XML machine, both item ports, menus, crafting recipes
and the creative tab.

`BaseMachineGameTests` check that every machine reads 3.0's `Energy` key, stops on redstone by default
and keeps a saved redstone setting, that idle machines save right after loading, and that broken
machines drop their contents once.
